*fpga_sv.txt*  Neovim 0.11+ SystemVerilog 工程支持

==============================================================================
1. 快速开始                                              *fpga_sv-quickstart*

>
  require("fpga_sv").setup()
<

在 <project>/.nvim-fpga.lua 写入：

>
  return {
    source_sets = {
      rtl = {
        roots = { "rtl" },
      },
    },
    profiles = {
      default = {
        source_sets = { "rtl" },
        top = "demo_top",
      },
    },
    default_profile = "default",
  }
<

首次使用：

  1. 创建 .nvim-fpga.lua。
  2. 接受项目配置的信任请求。
  3. 执行 :FpgaSvGenerate。
  4. 执行 :FpgaSvProjectInfo。
  5. 确认 Profile、Source Set 和文件数量正确。

插件使用 Slang、Verible/Conform、svlint 与 Tree-sitter，不在线安装工具。

==============================================================================
2. 配置放在哪里                                              *fpga_sv-config*

插件全局配置：

  <stdpath("config")>/fpga-sv.lua
  require("fpga_sv").setup({...})

用于工具路径、提示、按键和适配器等跨项目选项。全局文件示例：

>
  return {
    tools = {
      slang = { cmd = "slang-server" },
      svlint = { cmd = "svlint" },
      verible = { cmd = "verible-verilog-format" },
    },
  }
<

本机器件目录：

  :FpgaSvEditDeviceCatalog
  <stdpath("config")>/fpga-sv-devices.lua

用于多工程共享的厂商模型绝对路径。条目支持 depends_on、module_files、
files、filelists、roots、include_dirs、library_dirs、
library_extensions、defines 和 flags。depends_on 是有序器件 ID 列表，
支持多级、多父级和共享依赖去重。

module_files 以合法模块名为键、存在的绝对模型文件路径为值。只有活动
Profile 实际例化对应模块时才加入本地 .f；已选模型中的映射依赖会递归
加载，同一文件稳定去重，循环实例关系安全终止。依赖器件先合并，当前器件
的同名映射覆盖公共依赖。

推荐在器件目录顶部定义厂商 Root，再用 vim.fs.joinpath() 派生版本 Root、
系列 Root 和器件路径。厂商升级时只修改顶部 Lua 变量；插件不提供额外的
root/roots 字段。

任一器件依赖缺失、字段无效或路径不可用时，整套器件模型会被原子跳过，
项目 RTL 仍继续生成；Slang 此时可能报告 unknown module。

项目共享配置：

  <project>/.nvim-fpga.lua

用于可提交的 RTL、stub、Source Set、Profile、宏、include 目录和项目级
flags。快速开始中的配置就是最小共享配置。

项目本机配置：

  :FpgaSvEditLocalConfig
  <state>/fpga_sv/projects/<project-id>/config.lua

用于当前工程独有的本机工具路径和私有覆盖，不应提交。厂商模型绝对路径
优先放入本机器件目录。

合并顺序：

  内置默认值 < 全局文件 < setup() < 项目共享配置 < 项目本机配置

工具程序路径通常放全局或本机配置；RTL、stub 和项目统一编译参数放共享
配置；厂商安装路径放器件目录。修改后执行 :FpgaSvRefresh 或
:FpgaSvGenerate。

.slang/server.json 是 Slang 自身配置，不属于插件项目配置，也不能替代
活动 Profile 的 .f。插件不会创建、覆盖或迁移它。

3. Source Set 与 Profile                                    *fpga_sv-project*

工程链路：

  Source Set 定义文件集合
          ↓
  Profile 选择 Source Set
          ↓
  生成活动 Profile 的 .f
          ↓
  发送 slang.setBuildFile
          ↓
  Slang 分析完整工程

定义 Source Set 不等于启用 Source Set。profile.source_sets 决定当前构建
包含哪些集合。top 只指定顶层模块，不会自动收集依赖文件。是否属于工程
以活动 Profile 的 .f 为准；同目录文件不会自动加入。

项目 Lua 由 vim.secure.read() 加载。列表默认追加并去重，也支持
{ add, remove, replace }。文件和目录支持
{ path = "...", optional = true }。

==============================================================================
4. 字段摘要                                                *fpga_sv-fields*

Source Set：

  roots               相对 <project> 的源码扫描目录。
  globs               文件类型与递归范围；直属文件可用 *.sv。
  files               显式加入文件。
  module_files        仅器件目录；按实例把模块映射到绝对模型文件。
  filelists           导入 .f；嵌套路径相对当前 filelist。
  include_dirs        生成 -I，只搜索头文件，不编译目录模块。
  library_dirs        生成 -y，并按实际实例物化同名库文件。
  library_extensions  生成 +libext+...。
  defines             无值宏或带值宏。
  flags               原样传递额外编译参数。
  depends_on          Source Set 依赖与顺序。
  replaces            使用 stub 替换已收集源文件。
  exclude             排除目录或文件。

Profile：

  device              引用本机器件目录中的最终器件 ID。
  source_sets         必须显式列出启用集合；空列表生成空文件集合。
  top                 Slang 顶层模块名；唯一解析后发送源码路径。
  defines             Profile 专用宏。
  include_dirs        Profile 专用头文件目录。
  flags               Profile 专用参数。
  lint                Profile 专用 lint 配置。
  default_profile     首次加载的默认 Profile。

filelists 当前支持：

  - Verilog/SystemVerilog 源码路径。
  - -I、-D、-y。
  - +incdir、+define、+libext。
  - 嵌套 -f/-F。

厂商专用选项若带独立参数，应转换为插件字段，或制作只保留编辑分析内容的
wrapper .f。include_dirs 只能解决 `include，不能提供模块定义。

replaces 只移除已经由 roots、files 或 filelists 进入 model.files 的准确
路径，不能移除仅由 library_dirs 提供的模块。

5. 厂商原语库                                          *fpga_sv-primitives*

unknown module 的处理流程：

  1. 找到厂商提供且 Slang 能解析的 Verilog/SystemVerilog 仿真模型。
  2. 判断模型是每模块一文件、合并模型文件，还是厂商 .f。
  3. 执行 :FpgaSvEditDeviceCatalog。
  4. 建立 device_primitives 器件条目，并由 Profile.device 引用。
  5. 执行 :FpgaSvGenerate 和 :FpgaSvProfile edit_vendor。
  6. 用 :FpgaSvProjectInfo 检查活动 Profile、Source Set、本地 .f 和诊断。

按模块选择合并模型文件：

>
  local vendor_root =
    assert(vim.env.FPGA_VENDOR_ROOT, "请设置 FPGA_VENDOR_ROOT")
  local family_root = vim.fs.joinpath(
    vendor_root,
    "simulation",
    "family_a"
  )

  return {
    device_primitives = {
      module_files = {
        VENDOR_CLOCK_BUFFER =
          vim.fs.joinpath(family_root, "clock_models.v"),
      },
      library_dirs = { family_root },
      library_extensions = { ".v", ".sv" },
    },
  }
<

module_files 不扫描整个厂商目录，也不读取未命中的映射文件。已命中的文件
只进入本地 .f；:FpgaSvProjectInfo 显示实际命中和依赖覆盖关系。显式
module_files 优先于 library_dirs 自动搜索。

每模块一文件：

>
  local primitive_root = assert(
    vim.env.FPGA_PRIMITIVE_LIB,
    "请设置 FPGA_PRIMITIVE_LIB"
  )

  return {
    device_primitives = {
      library_dirs = { primitive_root },
      library_extensions = { ".v", ".sv" },
    },
  }
<

多模块合并文件时，将器件条目改为：

>
  device_primitives = {
    files = {
      vim.fs.joinpath(primitive_root, "primitive_models.v"),
    },
  }
<

厂商 filelist 时，将器件条目改为：

>
  device_primitives = {
    filelists = {
      vim.fs.joinpath(primitive_root, "primitive_models.f"),
    },
  }
<

slang-server 0.2.9 不会在 build-file 中通过 SourceLoader 展开
-y/+libext。插件会先预扫描已有模块定义，再按 library_dirs 顺序、然后按
library_extensions 顺序，非递归精确查找 <模块名><扩展名>。实际命中文件
显式进入 .f 和 model.files，文件内实例继续递归解析，同时仍保留 -y 和
+libext。未命中不阻断生成。文件名与模块名不一致或多模块合并文件仍应使用
module_files、files、filelists 或 stub。生成的 .f 只用于编辑分析，不承诺
可直接用于仿真或综合。

6. Stub                                                  *fpga_sv-stubs*

stub 没有插件专用格式。它是普通 .sv/.v 文件，通过 files 加入 Source
Set；一个文件可以包含一个或多个模块。保存为
stubs/device_primitives.sv：

>
  // 仅用于编辑分析，不用于仿真、综合或器件行为验证。
  module device_pll #(
    parameter int unsigned MULTIPLY = 8,
    parameter int unsigned DIVIDE   = 1,
    parameter string       STARTUP  = "WAIT_LOCK"
  ) (
    input  logic refclk,
    input  logic reset,
    output logic outclk,
    output logic locked
  );
  endmodule

  // 仅用于编辑分析，不用于仿真、综合或器件行为验证。
  module device_buf #(
    parameter string BUFFER_TYPE = "GLOBAL"
  ) (
    input  logic i,
    output logic o
  );
  endmodule
<

共享 .nvim-fpga.lua 定义 stub 和默认 Profile：

>
  return {
    source_sets = {
      rtl = {
        roots = { "rtl" },
      },
      primitive_stubs = {
        files = { "stubs/device_primitives.sv" },
      },
    },
    profiles = {
      edit_stub = {
        source_sets = { "rtl", "primitive_stubs" },
        top = "demo_top",
      },
    },
    default_profile = "edit_stub",
  }
<

器件目录按上一节定义 device_primitives；项目配置另建 edit_vendor，
设置 source_sets = { "rtl" } 和 device = "device_primitives"。
edit_stub 与 edit_vendor 必须互斥，避免真实模型和同名 stub 重复定义。

stub 必须与真实原语保持相同模块名；覆盖工程使用的参数名；匹配端口名称、
方向、位宽、数组和位置顺序；只保留接口，不实现时钟、延迟或器件行为。

验证：

  1. 分别切换 edit_stub 和 edit_vendor。
  2. 重新生成，检查活动本地 .f 只包含 stub 或真实库之一。
  3. 用 :FpgaSvProjectInfo 核对 Source Set 和文件数量。
  4. 搜索同名模块，排除重复定义。
  5. 核对参数覆盖、端口连接和诊断。

高级 replaces 仅适用于真实模型已经进入 model.files 的情况；通过
library_dirs 提供的真实模型必须使用互斥 Profile。

7. 生成产物                                            *fpga_sv-artifacts*

项目 .f：

  <project>/.nvim/fpga-sv/<profile>.f

本地 .f：

  <state>/fpga_sv/projects/<project-id>/generated/<profile>.f

slang.json 记录 Profile、build file 与 top。本地 .f 使用 -F 引用项目
.f。外部 .slang/server.json 可以继续保存索引和 hover 设置，插件不会
修改它；活动 .f 决定实际编译文件。

空 .f 常见原因：

  - Profile 未选择 Source Set。
  - Source Set 名称拼写错误。
  - glob 未匹配文件。
  - 路径被 exclude 排除。

==============================================================================
8. Slang 生命周期                                          *fpga_sv-slang*

插件复用标准 slang_server，不创建第二个自定义 Slang 客户端。

在 LspAttach 后，插件按缓冲区所属工程发送：

  slang.setBuildFile
  等待服务器成功回调
  在活动 Profile 索引中将 top 模块名解析为唯一源码路径
  slang.setTopLevel

:FpgaSvGenerate、:FpgaSvRefresh、配置保存和 :FpgaSvProfile 会重新发送
活动构建信息。setup() 也会补挂载已经打开的 Verilog/SystemVerilog
缓冲区。同一缓冲区只保留一个标准 slang_server，可用 :LspInfo 检查。

top 模块缺失或定义不唯一时，插件保留 build file，不发送无效的
slang.setTopLevel，并报告具体原因。

默认 keymaps.definition = "gd"。只有 gd 尚未被用户或 LazyVim 定义时，
插件才为当前 HDL 缓冲区创建映射。设为 false 可禁用。gd 调用
:FpgaSvDefinition，并使用当前附着 slang_server 的标准 definition 请求。
无客户端或无返回结果时，提示会包含活动 Profile 和 .f 检查方向。

9. 端口提示                                                *fpga_sv-hints*

提示是 virtual text，不会写入源码。模块声明位置由 hints.position 控制；
例化提示固定为 inline：

>
  counter u_counter (
    .clk         (← IN system_clk),
    .input_data  (← IN [15:0] source_data),
    .output_data (→ OUT [31:0] [3:0] result_array),
    .master_port (◇ IF stream_if.master stream_bus),
    .* AUTO:*
  );
<

支持命名连接、简写连接、位置连接、参数化例化和实例数组。模块定义缺失
或不唯一时不推测。.* 只显示 AUTO:*。

配置项：

  hints.enabled       总开关。
  hints.directions    方向文字。
  hints.dimensions    packed/unpacked 维度。
  hints.interfaces    interface 与 modport。
  hints.summary       模块端口统计。
  hints.automatic     .* 的 AUTO:*。
  hints.text          自定义文字。
  hints.highlights    自定义高亮。
  hints.position      仅控制模块声明提示。

默认文字：

  ← IN
  → OUT
  ↔ INOUT
  ↕ REF
  ◇ IF

10. 命令                                                 *fpga_sv-commands*

:FpgaSvProfile [name]        切换活动 Profile。
:FpgaSvGenerate              生成全部 Profile 产物。
:FpgaSvRefresh               重新加载配置、生成产物并刷新活动工程。
:FpgaSvProjectInfo           显示模块映射、库文件命中、文件数量和错误。
:FpgaSvDefinition            通过当前 slang_server 跳转到定义。
:FpgaSvEditGlobalConfig      编辑插件全局配置。
:FpgaSvEditDeviceCatalog     编辑本机共享器件目录。
:FpgaSvEditProjectConfig     编辑受信任的项目配置。
:FpgaSvEditLocalConfig       编辑 <state>/fpga_sv 中的本地配置。
:FpgaSvInstantiate [module]  插入命名端口例化。
:FpgaSvExpand                展开位置、简写和 .* 连接。
:FpgaSvHints                 开关并刷新端口提示。
:FpgaSvTop [module]          解析模块名并设置 Slang 顶层源码。
:FpgaSvLint                  lint 当前文件。
:FpgaSvLintProject           lint 活动 Profile 到 quickfix。
:FpgaSvTemplate {name}       展开 vim.snippet 模板。
:FpgaSvNext [kind]           跳到下一个结构。
:FpgaSvPrev [kind]           跳到上一个结构。
:FpgaSvSelect {kind}         选择当前结构。

兼容命令：

  SVInstantiate, SVProjectInfo, SVSlangSetBuild, SVSlangSetTop,
  SVPortDirectionsToggle

11. 排错                                                   *fpga_sv-trouble*

文件存在但模块未知：

  1. 检查活动 Profile 是否选择真实库或 stub。
  2. 执行 :FpgaSvGenerate。
  3. 检查 :FpgaSvProjectInfo 的 Source Set、文件数量和本地 .f。
  4. 检查命中的 module_files、库文件，以及 .f 中模型/stub、-y 与
     +libext。
  5. 不要把模块源码目录误写入 include_dirs。
  6. 合并模型文件使用 files，厂商 .f 使用 filelists。
  7. 排除真实模型与同名 stub 同时启用。
  8. 核对 stub 参数名、端口名、方向、位宽、数组和位置顺序。

gd 没有跳转：

  1. 用 :LspInfo 确认当前缓冲区附着 slang_server。
  2. 检查活动 Profile 和生成的 .f 是否包含目标源码。
  3. 已有 gd 映射时，直接执行 :FpgaSvDefinition 验证。

子目录模块可识别、直属文件不可识别：

  - 检查 globs 是否覆盖 *.sv 或 *.v。
  - 检查 Slang 是否收到活动 .f。

重复诊断：

  - 用 :LspInfo 检查 slang_server 数量；多个 slang_server 表示 LSP
    配置或自动启用逻辑重复。
  - 同时附着一个 slang_server 和一个 verible 属于正常情况，插件不会
    跨客户端合并诊断。
  - 只有一个 slang_server 时，旧版 Slang 可能在单次发布中包含精确
    重复项。插件仅合并完整 LSP Diagnostic 对象完全相同的项，属性不同
    的诊断仍会保留。

无端口提示：

  - 检查 hints.enabled 和活动 Profile。
  - 检查模块端口是否已索引。
  - 执行 :FpgaSvHints 刷新。

配置修改未生效：

  - 执行 :FpgaSvGenerate 或 :FpgaSvRefresh。
  - 检查配置是否受信任。
  - 检查 :FpgaSvProjectInfo 中的错误。

unknown module 通常是文件集合问题。timescale、implicit net、unused
signal 通常是真实 HDL 诊断。
